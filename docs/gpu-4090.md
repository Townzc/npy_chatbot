# RTX 4090：先完成真实 Qwen 单卡验收

2026-10-26：用户澄清将通过 AutoDL 租卡，目前没有已连接主机。首轮只租 **1 张标准 4090 24GB**，具体镜像、内存、数据盘和驱动见 [AutoDL 步骤](autodl.md)。标准 RTX 4090 每张 24 GB、无 NVLink；DDP 在每张卡上复制模型，不自动合并显存。当前 ChatTwin worker 明确是单卡实现。只有之后确实需要并行推理/评测时再考虑第二张。[NVIDIA 规格](https://www.nvidia.com/en-au/geforce/graphics-cards/40-series/rtx-4090/) · [PyTorch DDP](https://docs.pytorch.org/tutorials/intermediate/ddp_tutorial.html)

## 接入所需信息

- 实际租用主机的 Linux 发行版/架构、单卡分配主存、可用磁盘、NVIDIA 驱动。
- SSH 别名，或主机/用户名/端口。密钥与密码保留在本机，不写进文档、Git 或对话。
- 可先用 32GB 主机内存试跑，64GB 留更多余量；另预留 60GiB 可用磁盘。这些是容量规划建议，实际最低需求尚未测得。GPU 仍选一张 24GB 4090，无需 A800。

已有 Linux + NVIDIA 驱动可先检测。Windows 原生 CUDA 尚不在验收矩阵；若使用 WSL2，应单独记录发行版、驱动和 CUDA 可见性，不将其等同已测环境。无需模型 API 密钥；不自动租机或购买服务。

## 纯虚构数据、真实 Qwen 训练

以下在 GPU 主机的仓库根目录执行。安装固定依赖会下载 Python 包；运行训练会下载固定公开 Qwen 底座，数据不会上传到模型仓库。不会复制本机 `chat_record`。

```sh
uv sync --locked
uv sync --project training --locked
nvidia-smi --query-gpu=index,name,memory.total,memory.free,driver_version --format=csv
uv run chattwin train doctor
uv run python scripts/prepare_gpu_smoke.py --root "$HOME/chattwin-private/gpu-4090-check-001"
CUDA_VISIBLE_DEVICES=0 uv run chattwin train run "$HOME/chattwin-private/gpu-4090-check-001/spec.json"
```

`prepare_gpu_smoke.py` 仅从包内虚构对话建立独立档案、确认虚构身份、冻结数据集并生成 spec；它不读取默认数据目录，不训练、不下载模型，拒绝已有输出目录和 Git 内目录。这里的 smoke 使用真正的预训练 Qwen 4B；数据为虚构，模型不是 tiny 随机底座。训练通过也只证明 CUDA 执行链，不代表个人聊天质量通过。

首轮配置：BF16、LoRA rank 8 / alpha 16、q_proj/v_proj、最长 512 tokens、batch 1、梯度累积 4、最多 2 个 optimizer steps、最多 2 epochs，开启非重入梯度检查点。它减少保存的激活值、增加重新计算；未承诺 24 GB 一定足够。超长样本按现有规则跳过，不悄悄截断目标；检查 accepted/skipped 数量。[固定 Transformers 接口](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/modeling_utils.py)

已有冻结数据集可使用：

```sh
uv run chattwin train prepare /private/datasets/DATASET_ID /private/jobs/NEW_JOB /private/new-spec.json --profile rtx4090-dry-run
```

网页的“使用 4090 试运行配置”只填参数，不启动作业；梯度检查点参数随 API、spec 和下载的独立训练包保留。独立包仍默认不下载模型，需显式 `--allow-model-download`。

## 必须读取的结果

`train doctor` 只读取依赖、CUDA runtime、每张可见卡的名称/计算能力/总量/空闲显存及当前用卡。它不检查驱动性能或宣称训练通过。设置 `CUDA_VISIBLE_DEVICES=1` 后，原物理卡 1 在进程内通常显示为逻辑卡 0；以该次启动命令和 `nvidia-smi` 对照留证。

成功条件：

1. `status.json` 为 succeeded，实际 steps 非零；`training_report.json` 有有限、非零参数变化。
2. `adapter/adapter_model.safetensors` 与 manifest 匹配。
3. reload PID 与训练 PID 不同，base/adapter logits 有非零差异。
4. 记录 `hardware.json`、`peak_cuda_allocated_bytes`、`peak_cuda_reserved_bytes`、训练参数和驱动。两项峰值是训练父进程的 PyTorch 分配/保留峰值（含模型加载），不包括新进程重载、其他进程或全部驱动开销。用 `nvidia-smi` 补充整卡占用。

失败仍保留 status 和已有硬件报告；CUDA 失败状态会记录可读取的分配/保留峰值。OOM 不自动降级成 tiny、CPU 或假训练。先检查其他占用、缩短序列并创建新目录再测；当前没有 QLoRA、模型分片或 DDP，不能用 `torchrun` 宣称双卡训练。

训练完成后，可给独立推理进程选择另一张卡：

```sh
CUDA_VISIBLE_DEVICES=1 uv run chattwin model serve /private/jobs/SUCCEEDED_JOB --port 8766
```

按 training.md 在私有环境设置独立 `CHATTWIN_MODEL_TOKEN`；服务仅监听 loopback，可通过 SSH 隧道供 Mac 使用，不需要开放模型端口到公网。产物仍需登记、测试和本人选择启用。
