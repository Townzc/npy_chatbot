# 真实 QQ 登录、QCE 导出与 OneBot 只读探针 — 2026-10-27

本批是实际本机账号与官方 QCE/NapCat 进程的证据，不是本地模拟服务。用户本人扫码确认登录，并明确选定一个好友私聊；账号、备注名、UID/UIN、消息正文、文件名和私人报告均不进入本仓库。

## QQ 登录与 QCE 服务

- QQ 状态 API 实际返回 `isLogin=true`、`coreReady=true`、`loginPhase=ready`，无登录错误。
- QCE 实际返回版本 6.3.2、模式 `plugin`，健康检查 `online=true`。不是独立查看器模式。
- `lsof`：QCE HTTP 为 `*:40653`，内部桥为 `127.0.0.1:40654`，管理页为 `127.0.0.1:6099`。
- QCE 受保护 API：缺令牌 401、错误令牌 403、本机有效令牌 200；从本机非 loopback 地址携带有效令牌访问仍返回 403 / `IP_NOT_ALLOWED`。这不表示公开健康页或静态页面也拒绝所有非本机访问。
- 配置 API 返回的实际导出目录与私有 Application Support 目录一致。
- 浏览器已认证进入 QCE 并定位用户指定私聊；仅处理该会话。输入正文不作为工具指令执行。

- 首次新增 578 条，0 坏行；同文件再次导入新增 0 / 重复 578，持久消息及用途记录仍各为 578 条。原导出文件哈希不变。

- 修正划分预算：两条边界各保留一簇隔离，其余约 80% 给训练，剩余均分验证和测试；最少五簇也为三组各留一簇。过滤后任一保留组仍为空时，明确报告低可信，不把有分区等同有可评测样本。

## 真实 OneBot 只读探针

为落实早期接入验证，临时创建 `127.0.0.1:3001` 正向 WS，使用独立随机令牌；没有外部客户端、未选择接收人，ChatTwin `allow_send=false`。通过本项目实际 `OneBotAdapter` 发起 `get_login_info`、`get_version_info`、`get_status`，结果如下：

- 身份与本人当前 QCE 会话一致；实际协议版本 `NapCat.Onebot:4.18.28`，`online=true`、`good=true`。
- 错误令牌在 WebSocket 升级后收到 `retcode=1403` 并被断开。此实现不能仅凭 HTTP 升级成功判定认证通过。
- 显式错误的预期账号触发 `ACCOUNT_MISMATCH`，连接关闭。
- 测试结束移除本次临时服务，配置与原始基线一致，3001 不再监听。没有持久化未选中联系人的事件正文，没有调用消息发送 API。

这证明真实桥的只读连接与身份/状态核验，**不证明原私聊收发、通知顺序、回声、手机接管或 unknown 核对已验收**。`real_conversation_verified` 仍为 false。

## 本项目改动与回归

发现原探针在账号/版本通过后没有检查在线状态。`OneBotAdapter.open()` 现要求 `get_status` 的 `online` 和 `good` 均为布尔 true，随后才标记已验证；离线、不健康、字段缺失、字符串布尔、列表/null 状态均拒绝并关闭连接。返回摘要增加在线/健康结果。

6 项新增离线/异常状态回归，加上既有探针与发送权限测试，共 11 项 OneBot 单元测试通过。数据划分新增 6 项回归，覆盖 5/6/20/80 簇、末尾无可用问答、过滤后空测试集提示、后续导入不使冻结保留数据进入训练、旧快照不改写。核心全量 **176 passed / 1 skipped**，Ruff 检查及 87 文件格式检查、mypy 62 源文件通过。跳过项仍是核心环境未装可选训练 runtime；没有把这些测试称为 GPU 或真实消息发送证据。前端未改动，本批用已有生产构建执行真实网页→API→数据集验证。
