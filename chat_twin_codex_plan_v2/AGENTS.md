# ChatTwin 开发执行规则

## 任务与规范

阅读 DEVELOPMENT_PLAN.md、CODEX_START.md 和 docs/tasks.md。
目标是可运行的本地开源产品；无账号也能演示，QQ 与 GPU 路径有真实验收证据。
用户的新明确指令优先于本文件。对常规实现、调试和可逆测试直接推进；不要反复为已授权工作询问确认。

## 工作顺序

- 按 T01–T30 依赖推进，先 M0/M1 可运行闭环。
- M1 做纯模式契约与最小测试，M3 再补持久化、通知和并发集成。
- 核心契约与第一版迁移稳定后再并行数据、运行和产品三条线。
- 共享 schema、迁移编号、锁文件和控制状态机由集成负责人协调。
- 遇外部阻塞继续完成其他任务，准确标明 BLOCKED 或 UNVERIFIED。
- 不把空类、假训练、模拟 QQ 发送当作完成。

## 数据与模型

- Importer 独立于 ChannelAdapter；微信数据导入不等同微信原好友窗口回复。
- 原始 sender_id 保持来源事实；owner 按 Persona 目标身份映射，不能用昵称或导出者直接推导。
- 默认只训练经过确认的本人类 human 目标；AI/通知/未知来源不成为训练标签。
- 数据集按完整片段 split，再构造窗口；检索、画像和示例也受时间与最终测试集限制。
- 联系人、Persona、缓存、记忆、模型 adapter 都有范围。
- 删除训练来源不意味着旧权重自动遗忘。
- 真正 LoRA 必须参数更新、保存、新进程加载、推理与对照；无 GPU 的 tiny smoke 不能代替真实训练验收。

## 消息控制

- 精确默认文案：对方已切换为ai模式 / 本人已接管。
- 开启先通知确认再放行；接管先停止屏障，再显示停止和发送通知。
- 通知与 AI 回复共用唯一 outbox，按 kind 检查，不使通知等待 AI_ACTIVE。
- 模式与通知意图同一事务；command_id 幂等。
- 旧页面版本不能阻止本人接管；开启仍严格校验版本。
- Binding 不可变；改目标/档案创建新绑定，旧 outbox 不能重新定向。
- control_epoch 与 context_seq 分开；新来信不能取消必要模式通知。
- 认领后发起前的接管必须可测试；submitting 不是外部已提交的证据。
- unknown 先核对，不盲重发；已开始传输的请求不能保证撤回。
- 单个账号单个实际发送进程；运行时模型没有直接发送或 shell 权限。
- 故障/好友停用不冒称本人接管，重启不自动恢复托管。

## 安全与公开发布

- 真实聊天、数据库、API key、QQ会话、训练集、私人adapter在仓库外。
- 默认测试使用随包合成数据，无真实发送、无付费API。
- 新核心默认 Apache-2.0；不得移除上游许可证或捆绑受限桥程序。
- 实机测试使用实施会话中明确授权的账号和会话；本计划不授权向任意联系人发送。
- 用户未要求时不发布公共仓库、release或私人模型。

## 完成定义

每个任务更新：状态、实现文件、验证命令和结果、限制。
发布声明逐项对应实际证据，分别标模拟、真实本地、真实外部环境。
新增 API/模型字段同步生成 schema/前端类型，并跑相关契约测试。
测试覆盖真实风险，不追求无意义数量。一次有针对性的验证足够时继续推进。
